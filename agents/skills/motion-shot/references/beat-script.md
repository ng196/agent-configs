## The chain of realizations

Write this before any motion. Per beat:

```
viewer now understands: ___
because the previous beat showed: ___
and this beat is possible because: ___
```

The chain must survive being read as prose with no visuals. If two adjacent
beats don't depend on each other, one of them is decoration. The chain ends
on the payoff, not on the brand.

## The compatibility gate

| Topic shape | Verdict |
|---|---|
| An action changes a visible surface (search, merge, dedupe, send, fix, toggle) | Compatible — build the shot |
| A metric, threshold, architecture, or model choice | Not compatible — static diagram |
| A claim with no product action behind it | Not compatible — write the claim, don't animate it |
| Scale, coverage, "works across contexts" | Compatible only as an affordance in a shot about something else |

Decline in one line: "No visible state change — this wants a diagram, not a
shot."

## The beat line

One compact form per beat, written before motion:

```
BEAT  n · name
understand:  what the viewer now knows
proof:       the visible state change that shows it
object:      the single element followed (must be the same object as last beat)
action:      what happens to it
settled:     the frame the viewer must read (and how long it holds)
carries:     what passes into the next beat
camera:      push / pull / drift / chase + rough magnitude
sound:       the one cue tied to the change
```

If `object` changes between beats, justify it: either the old object becomes
the new one, or this is a new scene and the transition must carry something
recognisable across.

## The caption arc

The silent-film narration channel. Rules:

- Up to **three quick cards** to establish the problem, then the question, then
  the answer — e.g. `Three lists.` → `No shared ID.` → `Same name. Same shop?`
  → (later) `One entity.`
- Cards swap on a shared slot: words slide/emerge from below, old words leave
  upward. 350–550 ms of full visibility per card is enough for 3–4 words; a
  card that must be read gets 700 ms+.
- A small **mono technical line** may sit under a caption to carry units,
  counts, or the one term that needs precision. It is not a second caption.
- The final card is the promise, not the slogan: `One entity.`,
  `Two records → one row.`

## Timing table

| Move | Range |
|---|---|
| Word/typing ticks | 60–120 ms apart |
| Caption card swap | 350–550 ms visible |
| Row/element landing | 300–450 ms |
| Scene morph (object changes role) | 450–700 ms |
| Merge absorb | 350–450 ms, dock on a sound |
| Landing hold (must be understood) | 1.5–2.5 s |
| Camera push across a scene | 600–1100 ms, 4–13% scale |

Total budget: an 8–12 s shot carries 4–6 beats. If you need more than six,
the shot is two shots.

## Scale affordances

Use these instead of adding instance cards:

- **Dashed continuation rows** above and below a list, faded by a mask — the
  list becomes a window onto many.
- **A dotted spine** down the side of a panel.
- **A live count** that changes as the product works (`2,400 → 4 → 1`) — the
  number does the storytelling, at one position on screen.
- **Ghost chips** inside a container that collapse when the real filter runs.

Every affordance must be *disposed of* when its story ends, or it becomes a
stale label.

## Worked example — duplicate records become one entity

Bigram: 5 visible rows + dashed continuation, dashed ghost rows top and
bottom, count `2,400`. Beat 1 friction (rows land under a lifted search bar),
beat 2 evidence (matched tokens highlight in place — no mid-air connector
lines), beat 3 merge (the duplicate travels into the canonical row and is
absorbed), beat 4 payoff (the merged record slides out as a written output
row; the count lands on `1`). Captions: `Three lists.` → `No shared ID.` →
`Same name. Same shop?` → `Same street. Same city.` → `One entity.`

The same shape works for: two vendor SKUs collapsing to one product; two
alerts merging into one incident; two drafts resolving to one document.

## The premium pass

When asked to "make it premium", expand scope as planned beats — each with an
idea, a camera move and a sound event:

1. **Scale** — continuation affordances and a live count.
2. **Problem depth** — one more caption card plus its mono line.
3. **Technicality** — a real rule, unit or threshold, shown once.
4. **More samples** — more true rows, windowed; never invented ones.
5. **Camera** — one move per beat, including a chase on the payoff.
6. **Theme fidelity** — re-dress metaphors in the product's own palette.

Polishing the existing beats is not a premium pass. Name each new beat and
what idea it adds; if you cannot, it is decoration.

## Beat-check questions

**What am I showing? What does the viewer learn? Where does their eye go
next?** Any vague answer → revise the beat before animating it. Then ask:
remove this beat — which idea or feeling is lost? "None" means cut it.
